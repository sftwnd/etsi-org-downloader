# ADR-0010: Сборка через Maven Wrapper с настройками проекта

- Статус: Принято
- Дата: 2026-10-30
- Версия на английском: [ADR-0010](../0010-maven-wrapper.md)

## Контекст

Проект собирался тем Maven, который был установлен (#50): системным локально, Maven 3.9 из образа `maven` в Docker,
встроенным Maven в IDE. Другая версия Maven даёт другие версии по умолчанию для плагинов, не закреплённых в `pom.xml`,
а локальная сборка шла с пользовательскими настройками, их репозиториями и зеркалами; настройки проекта
`.settings.xml` (только Maven Central) использовала лишь сборка в Docker.

## Решение

- Maven Wrapper 3.3.4 в режиме `only-script`: `mvnw` и `mvnw.cmd` один раз скачивают Maven 3.10.0 в `~/.m2/wrapper`
  и проверяют SHA-256 дистрибутива из `.mvn/wrapper/maven-wrapper.properties`; бинарного `maven-wrapper.jar`
  в репозитории нет. Скрипты сгенерированы `maven-wrapper-plugin` 3.3.4 и совпадают со скриптами `crayfish-common-crc`.
- Настройки проекта — `.mvn/settings.xml`; `.mvn/maven.config` (`-s .mvn/settings.xml`) применяет их к каждой сборке
  вместо пользовательских.
- `run.sh` и образ Docker собирают проект через `./mvnw`. Этап сборки образа — образ JDK с `unzip`: без него `mvnw`
  скачивает дистрибутив `tar.gz`, который не совпадает с контрольной суммой `zip`.

## Обоснование

- Одна и та же версия Maven собирает проект на любой машине, в IDE и в Docker, поэтому сборка не зависит от того,
  что установлено.
- Контрольная сумма защищает от подмены дистрибутива: SHA-256 взят у zip, SHA-512 которого совпадает с `.sha512`,
  опубликованным Apache.
- `only-script` не держит в репозитории бинарных файлов: скрипт сам скачивает дистрибутив через `curl`, `wget` или Java.
- Настройки проекта делают источники зависимостей явными и независимыми от пользовательских настроек.
- Устройство повторяет `crayfish-common-crc`, так что проекты автора собираются одинаково.

## Последствия

- Первая сборка скачивает Maven 3.10.0 (9,6 МБ) в `~/.m2/wrapper`; Docker хранит его в кэше сборки.
- `.mvn/maven.config` задаёт путь к настройкам относительно текущей папки, поэтому Maven запускается из папки проекта:
  `run.sh` переходит в неё перед сборкой.
- IDE должна использовать wrapper (в IntelliJ IDEA: Maven home path — Use Maven wrapper), чтобы собирать тем же Maven.
- Новая версия Maven задаётся в `maven-wrapper.properties` вместе с SHA-256 её дистрибутива.
