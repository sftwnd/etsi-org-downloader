# ADR-0014: Один прогон одновременно на папку назначения

- Статус: Принято
- Дата: 2026-10-30
- Изменено: 2026-10-30 — код завершения 4 вместо 3, который JVM возвращает при OutOfMemoryError (#58)
- Версия на английском: [ADR-0014](../0014-run-lock.md)

## Контекст

Прогоны по расписанию могут наложиться друг на друга, а `docker compose up` и `docker compose run` — запуститься
одновременно (#62). Блокировки файлов `.part` сохраняют каждый файл целым ([ADR-0005](0005-part-file-download.md)),
но оба прогона обходят всё дерево: нагрузка на сайт удваивается, а второй прогон лишь соревнуется с первым за те же файлы.

## Решение

- Прогон держит исключительную блокировку операционной системы (`FileChannel.tryLock`) на файле `.etsiorg-downloader.lock`
  в папке назначения от начала обхода до его конца; `RunLock` захватывает и освобождает её.
- Блокировка берётся после подготовки папки назначения ([ADR-0001](0001-destination-local-paths.md)) и до первого
  запроса. Если её держит другой прогон, прогон пишет в журнал `Another run is mirroring to '<dest>'` и завершается
  с кодом 4 ([ADR-0008](0008-error-isolation-exit-code.md)); 3 — код JVM при `OutOfMemoryError`
  ([ADR-0016](0016-resource-limits.md)).
- Файл блокировки не удаляется: удаление занятого файла позволило бы третьему прогону заблокировать новый файл рядом
  с работающим прогоном.
- Процесс не открывает файл блокировки, который уже держит: закрытие другого канала этого файла в POSIX-системах сняло бы
  блокировку всего процесса.
- `Destination` не отображает на файл блокировки ни один ресурс сайта, в каком бы регистре ни было записано имя.

## Обоснование

- Операционная система снимает блокировку, когда процесс завершается, как бы он ни завершился, включая `kill -9`
  и остановленный контейнер: зависшей блокировке не нужны ни тайм-аут, ни ручное удаление, в отличие от файла, который
  отмечает прогон самим своим существованием.
- Контейнеры, монтирующие одну папку хоста, разделяют блокировки ядра, поэтому `docker compose up` и `docker compose run`
  исключают друг друга, как и два запуска `run.sh`.
- Собственный код завершения позволяет планировщику отличить наложение от сбоя: 4 означает, что ничего не сделано.
- Ресурс, заменивший файл блокировки, нарушил бы исключение, поэтому его имя зарезервировано, как и небезопасные пути.

## Последствия

- Два прогона не зеркалируют в одну папку одновременно; второй завершается сразу и без запросов.
- В папке назначения остаётся пустой файл `.etsiorg-downloader.lock`.
- Исключение надёжно настолько, насколько надёжны блокировки файловой системы. Сетевая файловая система может
  не передавать их между хостами, а Docker Desktop на macOS не передаёт их между хостом и контейнером: запуск `run.sh`
  и прогон контейнера в одну папку друг друга не исключают (проверено), а два контейнера или два процесса хоста —
  исключают.
