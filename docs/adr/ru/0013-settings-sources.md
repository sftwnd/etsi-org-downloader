# ADR-0013: Настройки — системное свойство, иначе переменная окружения, иначе значение по умолчанию

- Статус: Принято
- Дата: 2026-10-30
- Версия на английском: [ADR-0013](../0013-settings-sources.md)

## Контекст

Загрузчик читал настройки только из системных свойств `-Duri`, `-Ddest`, `-Dthreads` и `-Dzone` (#61). Контейнер
настраивают переменными окружения, поэтому образ получал свойства через `JDK_JAVA_OPTIONS`, и JVM при каждом запуске
печатала в поток ошибок `NOTE: Picked up JDK_JAVA_OPTIONS: …`; `docker-compose.yml` не мог передать настройку из своего
окружения. Аргументы командной строки молча игнорировались: опечатка вида `--dest=/data` запускала прогон с настройками
по умолчанию, а справки не было. `Main` сам читал свойства, поэтому его тесты меняли глобальные системные свойства.

## Решение

- `Settings` — значение настроек прогона: `uri`, `dest`, `threads` и `zone`. `Settings.of(properties, environment)`
  берёт настройку из её системного свойства, иначе из переменной окружения `ETSIORG_<ИМЯ>`, иначе это значение
  по умолчанию; значение обрезается по краям, пустое не считается заданным. Неверное значение, включая неверный путь
  папки назначения, — `IllegalArgumentException`, то есть код завершения 2
  ([ADR-0008](0008-error-isolation-exit-code.md)).
- Имена, смысл и значения по умолчанию настроек — перечисление `Settings.Key`; справка строится из него.
- `Main.run(args, properties, environment)` получает источники как функции: `main` передаёт `System::getProperty`
  и `System::getenv`, тесты — словари. Единственный аргумент `-h` или `--help` печатает в стандартный вывод способ
  запуска, настройки и коды завершения с кодом 0; любой другой аргумент — неверная конфигурация с кодом 2.
- `run.sh` передаёт `-h` и `--help` загрузчику, а остальные аргументы — JVM. Образ задаёт `ETSIORG_DEST=/data` вместо
  `-Ddest=/data`, а `docker-compose.yml` передаёт `ETSIORG_URI`, `ETSIORG_THREADS` и `ETSIORG_ZONE` из своего окружения
  или `.env`.

## Обоснование

- Контейнеры, юниты systemd и CI настраивают переменными окружения; системные свойства остаются для командной строки
  JVM и `run.sh`.
- Свойство важнее переменной: его задают для одного запуска JVM, а переменная может незаметно унаследоваться
  из окружения. logback тоже ищет свойство раньше переменной, например `NO_COLOR`.
- Пустое значение в обоих источниках означает «не задано»: `ETSIORG_THREADS=` в `.env` или `-Dzone=` дают значение
  по умолчанию, а не ошибку.
- Неизвестный аргумент останавливает прогон до начала, и опечатка в опции не зеркалирует весь сайт с настройками
  по умолчанию.
- Одно описание настроек служит и разбору, и справке, поэтому они не расходятся (DRY). `Main` только собирает прогон
  (SRP), а настройки тестируются без глобальных системных свойств и окружения.

## Последствия

- `JDK_JAVA_OPTIONS` больше не нужен для настроек; через него по-прежнему передаются опции JVM.
- Новая настройка — константа `Settings.Key`, поле `Settings` и её разбор; справка покажет её без изменений.
- У переменных префикс `ETSIORG_`, и они не пересекаются с окружением других программ.
