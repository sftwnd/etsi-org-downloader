# ADR-0010: Build with the Maven Wrapper and the project settings

- Status: Accepted
- Date: 2026-10-30
- Russian version: [ADR-0010](ru/0010-maven-wrapper.md)

## Context

The project was built with whatever Maven was installed (#50): the system Maven locally, Maven 3.9 of the `maven`
image in Docker, the Maven bundled with the IDE. Another Maven version brings other default versions of the plugins
that are not pinned in `pom.xml`, and a local build used the user settings with their repositories and mirrors;
the project settings `.settings.xml` (Maven Central only) were used by the Docker build only.

## Decision

- The Maven Wrapper 3.3.4 in the `only-script` mode: `mvnw` and `mvnw.cmd` download Maven 3.10.0 once into
  `~/.m2/wrapper` and check the SHA-256 of its distribution from `.mvn/wrapper/maven-wrapper.properties`; there is no
  binary `maven-wrapper.jar` in the repository. The scripts are generated by `maven-wrapper-plugin` 3.3.4 and match
  those of `crayfish-common-crc`.
- The project settings are `.mvn/settings.xml`; `.mvn/maven.config` (`-s .mvn/settings.xml`) applies them to every
  build instead of the user settings.
- `run.sh` and the Docker image build with `./mvnw`. The build stage of the image is a JDK image with `unzip`:
  without it `mvnw` downloads the `tar.gz` distribution, which does not match the checksum of the `zip`.

## Rationale

- The same Maven version builds the project on every machine, in the IDE and in Docker, so the build does not depend
  on what is installed.
- The checksum protects against a substituted distribution: the SHA-256 is that of the zip whose SHA-512 matches the
  `.sha512` published by Apache.
- `only-script` keeps the repository free of binaries: the script downloads the distribution itself with `curl`,
  `wget` or Java.
- The project settings make the sources of the dependencies explicit and independent of the user settings.
- The layout follows `crayfish-common-crc`, so the projects of the author are built the same way.

## Consequences

- The first build downloads Maven 3.10.0 (9.6 MB) into `~/.m2/wrapper`; Docker keeps it in the build cache.
- `.mvn/maven.config` gives the settings relative to the current folder, so Maven is run in the project folder:
  `run.sh` changes to it before the build.
- The IDE has to use the wrapper (in IntelliJ IDEA: Maven home path — Use Maven wrapper) to build with the same Maven.
- A new Maven version is set in `maven-wrapper.properties` together with the SHA-256 of its distribution.
